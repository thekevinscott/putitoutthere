- Fixed: a large failure dump now reaches the runner log intact instead of being cut off around 146KB. Writes to a pipe are asynchronous and `process.exit` discards whatever is still queued, and both engine entry points — the CLI binary and the Actions adapter the reusable workflow invokes — exited the instant the command resolved. Below 1 MiB the bug was invisible, because the maxBuffer kill above capped output before it could bite; raising the ceiling exposed it, and it truncated precisely the tail the previous entry exists to preserve. Both entry points now drain stdout and stderr before exiting. The exit codes, and the hard exit itself, are unchanged — draining explicitly rather than falling back to `process.exitCode` keeps a lingering keep-alive socket from delaying every release step. #664.
