- Fixed: a PyPI **first publish** is no longer left untagged. `pypi-tag` starts seconds after the caller's upload, and it identified "which versions are live" by reading PyPI's project-level `latest version` pointer — a Fastly-cached, eventually-consistent view that returns 404 until a brand-new project propagates. A 404 there is also the correct permanent answer for a project that was never released, so the engine concluded the package was unpublished, exited `0` with nothing to do, and the tag was silently never written (observed twice on a real consumer's `0.0.0`). The job now receives the versions the release run actually delegated and confirms them against PyPI's **immutable** per-version endpoint, which is never stale for a version that exists — and fails the job loudly if a named version really is absent, instead of passing silently.
