- Added: `delegated_packages`, a reusable-workflow output listing the PyPI packages a run handed to the caller-side `pypi-publish` job — `[{"name","version","tag"}, …]`, the set `pypi_pending` is the boolean for. Added alongside it: an `expect` input on `.github/workflows/pypi-tag.yml` (previously input-less), which takes that JSON verbatim. The canonical consumer template now wires the two together, so **the `pypi-tag` job in your `release.yml` needs updating** — see [migration notes](../migrations.d/2026-10-05-pypi-tag-now-takes-an-expect-input.md). Without `expect`, `pypi-tag` discovers versions from PyPI's mutable "latest version" endpoint, which lags an upload by minutes and 404s outright before a project's first release. [#694](https://github.com/thekevinscott/putitoutthere/issues/694).
