- Fixed: when a `kind = "pypi"` `[package.bundle_cli]` cross-compile produces no binary, the release step now prints the directory listing that says why instead of dying on its own diagnostic. The staging step's not-found branch still expanded `${BINARY_TARGET}`, the variable the gnu→musl mapping used to bind and #603 removed; under the step's `set -euo pipefail` that expansion aborts the branch, so a consumer debugging a missing binary got `BINARY_TARGET: unbound variable` in place of the listing. It reads `${TARGET}` — the triple the step actually built and staged from — so the failure path prints what it was written to print. #605.
