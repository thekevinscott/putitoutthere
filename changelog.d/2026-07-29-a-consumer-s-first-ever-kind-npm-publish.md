- Fixed: a consumer's **first ever** `kind = "npm"` publish now surfaces the bootstrap hint naming `NODE_AUTH_TOKEN` instead of a raw npm stderr dump. npm answers an unauthorized publish with `E404`, not `E401`/`E403` — confirming that a package exists but is not writable by you is itself an information disclosure — and `looksLikeAuthFailure` matched every auth code except that one. The result was that the bootstrap-paradox hint (npm trusted publishing binds to an already-published package, so the first publish has no OIDC path and must go through a token) was unreachable in precisely the situation it was written for: the exchange fails, setup-node's placeholder `_authToken` survives in `.npmrc`, the PUT comes back 404, and the operator got `npm error 404 Not Found - PUT …` with no indication that the fix is a one-time token. `E404` now matches. The widening stays narrow because the hint was already double-gated: it fires only when OIDC is the auth path **and** the packument probe confirms the package is genuinely absent from the registry. A 404 on a package that *is* published — a transient OIDC token-exchange failure, which is what piot's own `0.2.80` release hit — still surfaces the raw stderr unchanged, because telling that operator the package does not exist would send them to abandon trusted publishing over a blip. #598.
