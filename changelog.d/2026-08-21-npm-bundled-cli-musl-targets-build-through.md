- Fixed: a `kind = "npm"` `build = "bundled-cli"` package that **declares a `*-musl` target** builds and verifies again. #605 moved the Linux rows to `cargo zigbuild` at a pinned glibc floor, which is right for the gnu rows it was about, but it wired zigbuild only to the `*-linux-gnu*` cargo branch — and the step it replaced (`musl-tools` + `CC_<triple>=musl-gcc`) had run on *every* Linux row. A declared-musl row was left falling through to a plain `cargo build` with no C cross-compiler at all, so any crate compiling C sources (`libsqlite3-sys` bundled, vendored openssl, vendored libgit2 — the ones a musl consumer is told to enable) failed to link; and if it did compile, the new verify step failed it anyway, because that step treats static linkage as fatal on every Linux row while musl output is static-pie by construction. Musl rows now build through `cargo zigbuild --target "$RUST_TARGET"` (zig ships musl, so it is the C cross-compiler that replaced the apt one) with no glibc-floor suffix — a musl triple has no glibc to floor and `<triple>.2.17` is not a target zig accepts — and the verify step binds `RUST_TARGET` so its dlopen and `GLIBC_*`-ceiling assertions apply to gnu rows only. gnu rows are byte-identical to before. See [migration notes](../migrations.d/2026-08-21-npm-bundled-cli-musl-targets-build-through.md). #605.
