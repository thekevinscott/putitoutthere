- Changed: the reusable workflow's `bundle_cli — verify wheel contains <stage_to>/<bin>` step no longer requires `python3` or `unzip` on the release runner. It ran the check inline — `unzip -l | awk | grep` over the produced wheel, plus a `python3`/`tomllib` heredoc for the `[tool.maturin].python-source` parse — and now delegates to the engine's `verify bundle-cli` (#451), which reads the wheel with a dependency-free pure-Node zip reader. The contract is unchanged and verified identical at both test tiers: same wheel selection, same `python-source` subtraction (both the `python-source` and legacy `python_source` spellings), same `(^|/)<stage_suffix>/<expected>$` match, same `.exe` suffix on Windows rows, same `::error::` / `ok bundle_cli:` output and exit code. The one behavioral difference is the bug fixed below. Consumers using a `runs_on` image without `unzip` — or on a wheel row whose interpreter lacks `tomllib` — are the ones this reaches; nothing else changes. #595.
