- Fixed: `publish` now reports the **platform packages** a `kind = "npm"` `build = "napi"` / `"bundled-cli"` release shipped, instead of naming only the umbrella package. Such a release publishes one synthesized package per target alongside the umbrella — six packages for a five-target family — and the engine already knew which of them it published and which were already live (`publishPlatforms` returns `{ published, skipped }`), but the npm handler discarded the return, so the run report listed exactly one line. The run log is the only record of what a release actually did, which made a complete multi-package publish and a partial one that shipped the umbrella and stopped byte-identical from the outside; #624 was filed on precisely that misreading, and the report offered no way to rule it out. Each entry in the `--json` report's `published[]` now carries `result.platforms` — `{"published": [...], "skipped": [...]}`, registry names in publish order — and the human-readable render lists one indented `platform:` line per package. The `skipped` half matters as much as `published`: on a re-run after a partial failure it is what tells an operator the missing packages were already safely on the registry rather than lost. A handler that publishes no platform family (vanilla npm, crates, pypi) omits the key entirely rather than reporting an empty summary, which would read as a family that shipped nothing. The engine also logs the summary to stderr as the family lands, so a live run shows it before the final report. Purely additive — no existing field changes shape.
