- Added: `pypi_pending`, a publish-time reusable-workflow output, and `.github/workflows/pypi-tag.yml`, a reusable workflow that cuts the git tag for a PyPI package after your `pypi-publish` job has uploaded it. Both are part of the canonical consumer template (README → Quickstart): `pypi-publish` now gates on `if: ${{ !cancelled() && needs.release.outputs.pypi_pending == 'true' }}`, and a `pypi-tag` job (`needs: pypi-publish`) follows it. `pypi_pending` is `'true'` only when the release run actually reached your PyPI package and handed over its upload — narrower than the plan-time `has_pypi` in both directions, so a run that died in pre-flight cannot trigger an upload it never validated, and an idempotent re-run whose version is already live stops re-uploading files PyPI already has. `has_pypi` is unchanged and still emitted. #623.
