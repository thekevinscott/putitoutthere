- Added: `putitoutthere verify crate` — the crates-side sibling of `verify npm-tarball` (#443). Reads a published `.crate` back off the `cargo-http-registry` disk root the engine published to, extracts it, and asserts the crate ships its source tree (`src/lib.rs` or `src/main.rs` surfaces) — proof the publish shipped real contents, not an empty or silently no-op'd tarball. Absorbs the inline `.crate` verification block the reusable e2e workflow (`e2e-fixture-job.yml`, #334) carried as untested bash — same crates-row selection, same present-and-non-empty `.crate` guard, same `::error::`/`ok:` messages — into one colocated-tested engine command invoked from its former site (part of epic #442). Takes `--matrix <plan-json>` and `--registry-root <dir>`; unlike the npm sibling it reads local disk (same host, same job), so there is no HTTP download or retry. #449.
