- Fixed: `kind = "npm"` `build = "bundled-cli"` Linux binary is now always statically linked (musl). The engine's `bundle_cli — stage binary` step previously ran **before** `npm run build --if-present`. A consumer build script that also runs `cargo build --target $TARGET` (the raw `-linux-gnu` triple) and copies the result to `build/<triple>/` would overwrite the engine's musl binary with a glibc-linked one; the `bundle_cli — verify` existence check passed silently and the glibc artifact was uploaded to the registry. The stage step now runs **after** `npm run build --if-present` in both the reusable workflow (`_matrix.yml`) and the e2e mirror (`e2e-fixture-job.yml`), so the engine's musl binary always wins. The `bundle_cli — verify` step in `_matrix.yml` also now asserts static linking (mirrors the check present in `e2e-fixture-job.yml`).
