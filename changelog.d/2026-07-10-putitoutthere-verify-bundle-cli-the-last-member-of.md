- Added: `putitoutthere verify bundle-cli` — the last member of the `verify` family (#443, #449, #450). Asserts a maturin bundled-CLI wheel under `<path>/dist` contains its cross-compiled binary: the wheel's first `*.whl` must carry an entry whose path ends `<stage_suffix>/<bin>`, where `stage_suffix` is `--stage-to` with `[tool.maturin].python-source` (or the legacy `python_source`) subtracted from the front, and `<bin>` gains a `.exe` suffix on a Windows `--target`. This is the codified engine twin of the inline "bundle_cli — verify wheel contains `<stage_to>/<bin>`" bash block the reusable release workflow (`_matrix.yml`, #282/#358) carries — same wheel selection, same python-source stripping, same `(^|/)<stage_suffix>/<expected>$` match, same `::error::`/`ok bundle_cli:` messages and exit code — now colocated-tested, reusing the same dependency-free pure-Node zip reader as `verify wheel` (no `unzip`, Windows included). Takes `--path <pkg-dir>`, `--stage-to <dir>`, `--bin <name>`, and `--target <triple>`. `_matrix.yml` now calls this command instead of carrying its own inline copy — the `verify` surface `action.yml` was missing landed in #595. #451.
