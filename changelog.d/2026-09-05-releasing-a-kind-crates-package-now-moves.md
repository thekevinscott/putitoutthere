- Fixed: releasing a `kind = "crates"` package now moves the **in-repo version requirements that point at it**, instead of leaving them stranded on the version it just left. Two crates.io packages in one repo where A path-deps B (`b = { path = "../b", version = "0.2" }` — a `version` key alongside `path` is mandatory for any crate that also publishes to crates.io) used to break the moment B released outside A's declared range: cargo refuses to resolve at all with `failed to select a version for the requirement`, exit 101, before anything compiles or packages. Intermittent by nature — a repo on a patch cadence stays green until the first bump that leaves the range. #621 taught the build-time writers this; the publish path is the other half. Inline-table, section-table and `[workspace.dependencies]`-inherited requirements are all rewritten; registry dependencies and path dependencies pointing elsewhere are untouched. The pre-publish dirty-tree guard now recognizes every manifest the run rewrote, accumulated across the whole cascade rather than per package. #640.
