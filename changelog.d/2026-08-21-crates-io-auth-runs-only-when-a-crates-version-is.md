- Fixed: an idempotent re-run whose crates.io versions are already live no longer demands a working crates.io trusted publisher. The reusable workflow gated its `Authenticate with crates.io (OIDC)` step on the build matrix carrying a crates row — "does this repo have a crate?", which is true whether or not anything is left to publish — so the OIDC exchange fired even when every crates row would be skipped by `isPublished`, and a failing exchange (trusted publisher not registered yet, or a record that hadn't propagated) failed the whole `publish` job before the engine action ran, taking npm and PyPI with it. That is the ordinary re-run-after-partial-failure state `isPublished` exists to make safe: a repo whose crate is current could not re-run to finish an unrelated registry. `plan` now emits an `unpublished_kinds` step output — the registry kinds carrying at least one package whose planned version is not already live, from the same `handler.isPublished` the publish path dispatches through — `_matrix.yml` re-exposes it as a `workflow_call` output, and the OIDC step gates on that instead. A kind whose registry could not be reached stays listed, so a blip never silently drops a credential the publish still needs; the caller-provided-token export steps keep the wider matrix gate, since writing an env var cannot fail the job. Consumers need no changes — the reusable workflow's inputs, outputs, and every other behavior are unchanged.
