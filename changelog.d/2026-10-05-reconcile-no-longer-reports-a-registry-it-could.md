- Fixed: `reconcile` no longer reports a registry it could not read as "nothing to do". A package whose registry lookup failed produced the exact `{"ok":true,"dryRun":false,"actions":[]}` output as a fully-tagged repo, so a `pypi-tag` run that lost a tag was indistinguishable from one with no work. Such rows are now listed under a new `skipped` key on the JSON result (`[{package, kind, reason: "registry-unreachable"}]`) and each emits a `::warning::` annotation naming the package and registry. The job still exits `0`: `reconcile` walks every configured package, so a crates.io blip must not red-light a consumer's PyPI tagging. A package that is simply unpublished is deliberately **not** reported — a registry answering "no such version" has answered, and every unshipped package is in that state permanently. [#694](https://github.com/thekevinscott/putitoutthere/issues/694).
