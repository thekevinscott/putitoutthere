- Fixed: a failed tag push during `publish` or `reconcile` no longer exits `0`. `ensureTag` (#407's auto-heal) caught any failure from `git push` and downgraded it to a `log.warn`, so a version could go live on the registry with no tag pointing at it and the run still reported success — the write-side twin of the read-side silent-success #694 fixed. A push failure now throws (`[PIOT_TAG_PUSH_FAILED]`, with the original git error chained as `.cause`), and the message says plainly that the registry write already happened, so the fix is `reconcile`, not a re-run of `publish`. Idempotency also moved off a local-only check: `ensureTag` treated any local `git tag -l` hit as "already done," which cannot tell a tag that was pushed from one that was only created before a prior push failed — it now asks `origin` directly (`git ls-remote --tags`) and retries just the push when the local tag exists but the remote doesn't.
