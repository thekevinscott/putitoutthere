- Fixed: `kind = "npm"` `build = "bundled-cli"` platform packages whose artifact stages the binary **nested** (`artifacts/<pkg>-<triple>/bin/<bin>` rather than flat) now publish a usable tarball. The engine picked the synthesized package's `main` by taking the first non-`package.json` entry `readdir` returned, without checking it was a file — on the nested layout that entry is the `bin` *directory*, which both layouts reach because the artifact completeness check lists files recursively. Two consequences, both consumer-visible: the published manifest declared `"main": "bin"`, pointing at a directory (live example: `@agent-transcripts/x86_64-unknown-linux-gnu@0.0.1`), and the #365 executable-bit restore chmodded that directory instead of the binary, so the tarball shipped the binary at 0644 — exactly the condition #365 exists to prevent. It was masked for consumers using the generated launcher (it re-chmods at spawn time) and an `EACCES` for anyone execing the binary directly or using a different launcher. `main` now resolves through directories to the binary itself (`bin/<bin>`, posix-separated) and the chmod lands on it. Flat artifacts are unchanged, and `build = "napi"` was never affected — it looks its `.node` payload up by extension. See [migration notes](../migrations.d/2026-08-21-npm-bundled-cli-main-resolves-to-the-binary-not.md). #626.
