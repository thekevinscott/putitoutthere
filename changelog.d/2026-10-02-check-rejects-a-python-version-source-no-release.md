- **BREAKING** Fixed: `check` now rejects a `kind = "pypi"` package whose `dynamic = ["version"]` names a version source a release run cannot actually reach, instead of accepting any `[tool.hatch.version]` / `[tool.setuptools_scm]` block on sight. Two shapes passed preflight and then published the *previous* release's version. The first is plain hatchling with `[tool.hatch.version] path = "src/<pkg>/_version.py"` (or `source = "code"`): it satisfies the `PIOT_PYPI_STATIC_VERSION` gate because the version is declared dynamic, and satisfied the old `PIOT_PYPI_DYNAMIC_VERSION_NO_BACKEND` gate because a version table was present — but hatchling reads a literal out of that file, ignores the `SETUPTOOLS_SCM_PRETEND_VERSION` the reusable workflow exports, and no release step rewrites it (`write-version` is maturin-only), so the wheel carries whatever is committed. `thekevinscott/agent-transcript-viewer` uploaded `0.0.0` to PyPI that way while the plan said `0.1.0`, with every check green — exactly the ["no release surprises"](../notes/design-commitments.md) failure the PR-time gate exists to prevent, and unrecoverable after the fact because PyPI does not allow re-uploading a version. It is now `PIOT_PYPI_HATCH_VERSION_PATH`, a separate code from the missing-backend one because the remedy differs: switch the source, rather than wire up a plugin. The second shape is a version table whose plugin is not installed — `source = "vcs"` without `hatch-vcs` in `[build-system].requires` (hatchling dies mid-build with `Unknown version source: vcs`), or `[tool.setuptools_scm]` without `setuptools-scm` there — now reported as `PIOT_PYPI_DYNAMIC_VERSION_NO_BACKEND` at PR time rather than discovered mid-release. Plugin names are matched per PEP 503, so `setuptools_scm>=8`, `hatch-vcs ; python_version < '3.9'` and `Setuptools-SCM` all count as declared. `build = "maturin"` is unaffected — its version comes from the sibling `Cargo.toml`, which the release path does bump — and both fires are reported by `check` at PR time *and* by publish-time preflight, so a repo that skips `check.yml` is still stopped before any upload. A version table that is not a TOML table no longer counts as a version source either: the old presence test accepted any non-null object, so the array-of-tables typo `[[tool.hatch.version]]` (or `[[tool.setuptools_scm]]`) passed preflight and then produced no version at build time — it is now `PIOT_PYPI_DYNAMIC_VERSION_NO_BACKEND`. A consumer on the file-path shape will see `check` go red on upgrade; that red is the bug it was shipping.
