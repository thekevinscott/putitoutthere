- Fixed: releasing a crates.io package that inherits its version (`version.workspace = true`) now bumps that version at its real source, the workspace root's `[workspace.package].version`, instead of rewriting the first `version = "…"` it finds after the `[package]` header — which, with no literal version in that table, was a **dependency's requirement** in a section table. Such a release used to leave the package's own version untouched and silently pin an unrelated dependency to the release version, naming a release of that dependency which does not exist. The publish path now routes through the same workspace-inheritance resolver the maturin and bundled-cli/napi pre-build writers have used since #428, and the pre-publish dirty-tree guard recognizes the workspace-root manifest as a managed write rather than a stray edit. #639.
